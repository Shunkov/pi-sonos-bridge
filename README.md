# Pi Sonos Bridge

**Turn a Raspberry Pi into a Line-In + Bluetooth receiver for Sonos.**

Plug a turntable, CD player, TV or any line-level source into the Pi, pair
your phone over Bluetooth — and play either (or both) on any Sonos speaker
in the house. No Sonos Port (£399) required.

```
 phone ──Bluetooth A2DP──┐
                         ├──► PipeWire mix ──► ffmpeg (MP3) ──► Icecast ──► Sonos
 turntable/CD ──line-in──┘        http://<pi>:8000/stream.mp3
```

## How it works

Both inputs are looped into a virtual PipeWire sink. A small Python service
(stdlib only — no pip installs) runs ffmpeg capturing that sink's monitor,
encodes MP3 at 192 kbps, and publishes it to a local Icecast server. Sonos
plays it as a custom radio stream — the one format every Sonos generation
supports natively. Switching inputs mutes/unmutes loopbacks, so the stream
(and Sonos) never disconnects. Full design: [docs/architecture.md](docs/architecture.md).

## Quick start — on a Raspberry Pi

You need a Pi with a **line-in interface** (USB audio interface or ADC HAT —
no Pi has line-in built in; see [docs/hardware.md](docs/hardware.md)).

```bash
git clone https://github.com/Shunkov/pi-sonos-bridge.git
cd pi-sonos-bridge
./scripts/install.sh
```

The installer sets up Icecast, the Bluetooth A2DP receiver (discoverable,
"Just Works" pairing), the audio routing, and systemd services that start
at boot. It prints your stream URL when done.

Then either:

- **One command:** `python3 tools/sonos_discover.py` to find a speaker, then
  `python3 tools/sonos_play.py <speaker-ip> http://<pi-ip>:8000/stream.mp3`
- **Or in the Sonos app:** add the URL as a custom radio station —
  step-by-step in [docs/sonos-setup.md](docs/sonos-setup.md).

Control inputs (Mix / Line-in only / Bluetooth only / Mute), restart the
stream, and check Bluetooth pairing in the web UI: **http://\<pi-ip\>:8080**

## Try it without hardware (Docker)

```bash
ICECAST_SOURCE_PASSWORD=pick-a-password docker compose up --build
```

Streams a 440 Hz test tone, so you can verify the whole Sonos side before
buying any audio hardware. Add `http://<this-machine-ip>:8000/stream.mp3`
to Sonos and you should hear the tone.

## Configuration

All via environment (`/etc/pi-sonos-bridge.env` on the Pi — see
[.env.example](.env.example)):

| Variable | Default | Meaning |
|---|---|---|
| `AUDIO_MODE` | `pipewire` | `pipewire` (both inputs) · `direct` (line-in only, via ALSA) · `test_tone` |
| `ALSA_DEVICE` | `hw:2,0` | ALSA device for `direct` mode |
| `LINEIN_SOURCE_MATCH` | `alsa_input.usb` | Which PipeWire source is the line-in |
| `AUDIO_BITRATE_KBPS` | `192` | MP3 bitrate |
| `ICECAST_SOURCE_PASSWORD` | *(generated by install)* | Password ffmpeg uses to publish the stream |

## Honest limitations

- **Delay is ~2–5 seconds** end to end (Bluetooth + MP3 + Icecast + Sonos
  buffering). Great for music and radio; useless for TV lip-sync.
- Bluetooth receive is SBC/AAC (that's what BlueZ/PipeWire supports) —
  no aptX/LDAC.
- One shared stream: both inputs mix unless you pick one in the web UI.
- Pi + speakers must be on the same LAN subnet.

Help for common problems: [docs/troubleshooting.md](docs/troubleshooting.md).
